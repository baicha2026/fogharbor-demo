# 雾港守灯人：Steam-ready 多路线大型版设计规格

日期：2026-10-11  
状态：已由 Godot 4 原生 3D 修订规格替代；保留此文件作为原 Streamlit 方案记录。
目标：原 Streamlit 方案记录。因用户要求精细 3D 建模、骨骼动作和动画命中帧，最终玩家端已迁移至同日期的 Godot 4 修订规格。

## 1. 已确认范围

- 实现路线：方案 A，保留现有 Streamlit 前端、纯 Python 剧情 / 战斗引擎、FastAPI 后端和 EXE 打包链。
- 关卡：11 个手工关卡；共享序章 2 关，每条路线 3 关。
- 分支：3 条路线、3 个主要结局。关键选择必须改变地图组、敌人组合、奖励池、最终首领和结局结果，不能只替换对话。
- 技能：11 本技能书；每次装备 4 个主动技能；所有技能拥有短时可见特效和结算反馈。
- 节奏：技能表现目标 0.6 秒，首领大招最多 1.2 秒；效果持续回合与动画时长分离；提供跳过特效和低特效模式。
- 发布边界：Steam-ready Windows 单机包。支持离线游玩、自动 / 手动存档、本地成就统计、键盘和手柄映射、Steamworks Bridge 占位。无真实 App ID 时不依赖 SDK。
- 用户约束：源码、缓存、构建、存档与输出均放在 `E:\0`；不读写 C 盘；ComfyUI 和 DeepSeek 都是可选服务，默认离线可玩。

## 2. 玩家流程与关卡结构

### 2.1 共享序章

1. **避风站**：洛恩交付灯塔任务，艾芙开启药剂支线，玩家学习移动、互动、购买与恢复。
2. **灯塔遗迹**：玩家完成三枚灯芯的基础目标，在遗迹核心看到三种理念选择，选择结果写入存档并锁定路线。

### 2.2 守灯路线

- **盐雾滩**：护送港口工人，布置补给点，学习守点和防御。
- **灰烬码头**：保护燃料车穿过灼烧区域，遭遇远程与护甲敌人。
- **灯塔圣坛**：灰烬领主多阶段战；结局为守住港口、点亮灯塔。

### 2.3 逐潮路线

- **沉矿井**：机关、窄路和伏击，学习破甲与路线选择。
- **潮汐洞窟**：水位和迟缓区域，学习净化、位移和异常管理。
- **深海裂隙**：潮汐核心多阶段战；结局为封印迷雾源头。

### 2.4 破誓路线

- **回声钟楼**：高风险精英组合战，允许以生命换取强化。
- **沉没档案馆**：钥匙、隐藏房间和高价值技能书，学习诱饵与复制机制。
- **深海王座**：王座守卫与最终深海权能；结局为接受深海力量，成为新的雾中守望者。

每张地图使用统一的关卡数据契约：`id`、`name`、`tiles`、`spawn`、`exits`、`objective`、`entities`、`rewards`、`palette`、`dialogue_nodes`。载入时校验 10×10 布局、出生点可达、目标可达、实体不越界和唯一奖励 ID。路线锁定后，非当前路线的地图和奖励不会出现在本局。

## 3. 战斗与技能系统

### 3.1 敌人

保留锈齿潜伏者、潮雾胶灵、失航骸骨和熄灯者，并增加：

- 盐壳蟹：护甲、破甲窗口。
- 灰烬灯蛾：灼烧、空中位移。
- 钟摆傀儡：蓄力眩晕、可被防御打断。
- 深潜猎手：远程鱼叉、拉拽。
- 潮汐女巫：减益、召唤。
- 迷雾镜像：复制玩家上一行动。

路线精英 / 首领分别为灰烬领主、潮汐核心和深海王座守卫。每个首领至少 2 个阶段，阶段切换必须有预警事件和可读日志。

### 3.2 状态与数值

统一状态结构：`id`、`source`、`remaining_rounds`、`stacks`、`magnitude`。首轮实现灼烧、迟缓、破甲、恐惧、护盾；每个状态定义施加、每回合结算、解除条件和日志文案。状态图标与剩余回合显示在战斗面板。

保留高伤长冷却、低伤回蓝、防御和药剂的基础循环。每回合先校验资源与 CD，再播放表现并结算玩家动作，最后结算敌人反击和状态；非法动作不推进回合、CD、特效或存档。

### 3.3 技能书与主动技能

共 11 本技能书：每条路线 3 本专属技能书，另有 2 本隐藏技能书。技能书获得后显示“学习 / 暂不学习”，学习结果持久化；战斗前从技能库配置 4 个主动技能。技能类型覆盖单体爆发、范围攻击、护盾反击、净化 / 回蓝、破甲、灼烧、位移、召唤诱饵和牺牲生命换伤害。

每个技能契约包含：`id`、`name`、`cost`、`cooldown`、`targeting`、`damage`、`status_effects`、`animation_key`、`telegraph`、`route_requirement`。`animation_key`只引用本地特效模板，不允许技能逻辑直接操作 Streamlit UI。

### 3.4 表现与时间控制

战斗事件写入 `battle_fx`：`kind`、`skill_id`、`target`、`color`、`intensity`、`created_at`、`duration_ms`。UI 根据事件渲染角色闪白、弹道 / 范围标记、粒子、伤害数字、状态图标和短暂屏幕闪光；规则引擎仍以离散回合为唯一事实来源。

- 普通技能表现目标 300–800ms。
- 首领大招表现上限 1200ms。
- 持续状态的回合数不等于动画播放时长。
- 设置中提供“完整 / 简化 / 跳过”三个特效档位；跳过只跳过表现，不跳过结算和日志。

## 4. 美术、海报与素材边界

- 延续本地 Kenney Tiny Dungeon CC0 图块，新增地图调色板、敌人重着色 / 轮廓、路线色、标题卡、状态图标和程序化粒子，所有运行时素材从项目或 EXE 资源读取。
- `battle_scene` 改为按敌人类型、阶段和路线读取表现配置；找不到配置时使用安全的默认角色和颜色，不阻塞战斗。
- 本地海报使用 Pillow 合成角色、首领、奖励徽章、路线配色和英文安全字体文本；不读取系统字体，不依赖 GPU 或网络。
- `generate_achievement_poster` 捕获 ComfyUI 超时、连接异常、无效 JSON、任务失败和图片校验失败，统一回退 `placeholder_poster`，返回可展示、可下载的合法 PNG 结果。
- 海报结果始终包含 `image_base64`、`mime_type`、`item_name`、`source`、`notice`；前端不对缺字段做未保护的索引。

## 5. 存档、成就与 Steam-ready 包

### 5.1 存档

存档版本为整数，顶层包含 `save_version`、`saved_at`、`route_id`、`choice_flags`、`map_progress`、`skills_unlocked`、`equipped_skills`、`achievements`、`stats` 和完整游戏状态。写入临时文件后原子替换；损坏文件改名为 `.broken` 并提示玩家。提供迁移函数，旧版本缺字段使用明确默认值，不静默覆盖玩家进度。

保存点：路线选择、进入 / 完成关卡、学习技能书、首领战结束、手动保存和退出前。保存位置为 EXE 旁 `.runtime/saves/slot-1.json` 至 `slot-3.json`。

### 5.2 成就与统计

本地成就至少包括：首次通关、三条路线各自通关、学习第一本技能书、收集全部技能书、无伤完成关卡、完成三结局。统计至少包括击杀、受击、最大连击 / DPS、技能使用次数、技能真空回合、已探索地图格。`SteamBridge` 提供 `init`、`unlock_achievement`、`set_stat`、`shutdown`，默认实现记录本地 JSON；未来提供 App ID 和 SDK 后再替换适配器。

### 5.3 启动与操作

EXE 启动器只显示玩家可见状态和“打开游戏 / 退出”；启动本机后端与前端，默认打开本地游戏页面。键盘支持 WASD、方向键、E、Esc、1–4；浏览器 Gamepad API 映射左摇杆、A、B、肩键，未连接手柄时隐藏说明。网络服务仅绑定 `127.0.0.1`。

## 6. 测试与验收

### 6.1 单元 / 集成测试

- 11 张地图均为 10×10，目标和出口可达，路线锁定后不会串线。
- 三条路线各自完整通关并产生对应结局，选择和奖励不会重复结算。
- 11 本技能书可获得、学习、保存、读取和配置；4 槽限制生效。
- 所有技能至少产生一个 `battle_fx`，特效档位不改变战斗数值。
- 状态效果回合结算、解除、死亡和存档迁移可重复验证。
- 海报接口在 ComfyUI 正常、超时、连接拒绝、错误 JSON 和空图片时都返回 PNG。
- 存档原子写入、损坏备份、三槽隔离和旧版本迁移通过测试。

### 6.2 浏览器 / EXE 验证

从独立目录复制 EXE，清空 PATH，不提供源码、API Key、DeepSeek 或 ComfyUI。真实启动后验证：新游戏、继续游戏、路线选择、技能书、至少一场首领战、海报下载、三路线结算和服务关闭清理。生成版本清单、SHA256、测试摘要和 Steam 发布素材索引。

## 7. 非目标与风险

- 本轮不伪造 Steam App ID、不上传 Steamworks、不承诺商店审核通过。
- 不把 Streamlit 伪装成原生 3D 客户端；方案 A 的交付是可离线运行的本地 Web 游戏 EXE。
- 当前 Kenney 资源量有限，新增敌人优先采用重着色、轮廓和程序化特效；如需要完全原创角色立绘，应另行提供素材或授权。
- DeepSeek / ComfyUI 的在线质量受外部服务影响，离线规则和本地海报必须始终可用。
- 三路线内容、11 张地图和 11 本技能书会显著增加测试量；必须先完成数据契约、保存和规则层，再扩展 UI 与发布验证。

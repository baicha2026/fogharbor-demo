# 雾港守灯人：Godot 4 风格化 3D 多路线大型版设计规格

日期：2026-10-11  
状态：待用户审阅；审阅通过后才编写实现计划并开始编码  
目标：把《雾港守灯人》从 Streamlit 像素回合制原型升级为 Godot 4 原生、45°俯视的风格化 3D 动作策略游戏。最终客户端使用可见的 3D 角色模型、骨骼动作、实时命中帧和短时技能特效；Python 与 Streamlit 保留为策划验证、数据分析与可选 AI 服务，不再承担玩家端画面。

## 1. 已确认范围

- 最终客户端：Godot 4 风格化 3D；镜头为 45°俯视动作策略视角。
- 内容：11 个手工关卡；共享序章 2 关、守灯 / 逐潮 / 破誓三条路线各 3 关。
- 分支：3 条路线、3 个主要结局。路线选择改变地图、敌人组合、技能书、奖励、首领和结局，不只是替换文本。
- 技能：4 个初始主动技能，11 本可学习技能书；战斗中装备 4 个主动技能。
- 角色表现：英雄、NPC、普通怪、精英与首领使用真实 3D 模型和骨骼动画。不能以静态贴图或点击后直接改数值替代动作。
- 战斗表现：每个技能都有前摇、动作、攻击范围或弹道、命中帧、受击反馈、伤害数字和状态特效。普通技能表现 300–800ms，首领大招最多 1200ms。
- 发布边界：Steam-ready Windows 单机包。支持离线运行、自动与手动存档、本地成就和统计、键盘与手柄、Steamworks Bridge 占位；不伪造 App ID、不上传 Steamworks、不承诺商店审核通过。
- 存放约束：项目、Godot 缓存、下载素材、构建、存档和输出全部位于 E:\0；不使用 C 盘。

## 2. 已知起点与迁移决定

现有工程是 Python、Streamlit、FastAPI 和 Pillow 构成的 2D 像素原型，已验证剧情、任务状态、数值记录、DPS 图和 ComfyUI 回退接口。检查结果显示 E 盘当前没有 Godot、Blender、Godot 场景或可复用的 3D 模型文件。

因此，原 Streamlit 大型版不再作为最终玩家端。它保留为技术策划验证台，负责数值推演、任务 JSON、关卡数据、DPS / 热力图和 AI 服务；新建 Godot 4 原生客户端承载 3D 场景、角色、动画、输入、战斗、存档和 Windows 导出包。旧规则只可作为数值参考，不能绕开动画直接驱动最终客户端的伤害结算。

## 3. 技术架构

Godot 4 原生玩家端负责离线游戏核心、3D 场景、导航、骨骼动画、粒子、音效、本地存档、成就和 SteamBridge。Python 策划验证工具负责数值、DPS、关卡与任务分析。Godot 客户端仅在可选增强模式下请求 FastAPI 的 DeepSeek 与 ComfyUI 服务；服务不可用时使用本地任务和海报回退。

新建 E:\0\godot_client，由 Godot 4 管理。模块边界如下：

| 模块 | 职责 | 不负责 |
| --- | --- | --- |
| GameState | 路线、任务、关卡、背包、技能书、结局与存档状态 | 渲染节点细节 |
| CombatResolver | 命中、伤害、护甲、状态、CD、MP 与敌方行为 | 播放动画或直接操作 UI |
| PlayerController | 移动、锁定目标、输入缓冲、技能请求 | 决定伤害数值 |
| CharacterPresentation | AnimationTree、模型朝向、受击、特效触发 | 修改规则状态 |
| LevelController | 地图目标、出口、事件、刷怪、奖励触发 | 跨关卡永久数据 |
| SaveService | 三存档位、自动存档、迁移、损坏备份 | 直接连接 Steam SDK |
| SteamBridge | 本地成就与统计；未来 Steamworks 适配点 | 依赖未提供的 App ID |
| AiGateway | 可选 DeepSeek 任务与 ComfyUI 海报请求 | 阻塞离线主线 |

Python 服务只接受结构化、大小受限的请求。AI 不可改写剧情推进、伤害公式、存档或路线锁定。

## 4. 实时动作战斗、动画与命中时点

最终客户端采用实时动作策略，而不是沿用浏览器版的点击即结算回合制。镜头为固定偏移的 45°透视 Camera3D，角色使用 CharacterBody3D、碰撞体、导航网格和目标锁定；玩家可移动、翻滚、攻击、施法、躲避和打断，敌人使用可读的蓄力与攻击窗口。

点击或按下技能只会发出技能请求。系统先验证资源、CD、目标距离、移动状态和角色状态；通过验证后，角色进入相应动画状态。动画在定义的命中帧发出命中信号，CombatResolver 才结算伤害、状态与敌方反应；命中后的冲击事件再驱动特效和 UI。非法输入不开始动作、不推进 CD、不写存档。

每个战斗角色使用 AnimationTree 与 AnimationNodeStateMachine：

Idle → Move → AttackLight / AttackHeavy / Cast / Dodge → Recover

该链可被 Hit、Stun、Death 和首领阶段状态中断。AnimationPlayer 的命中、脚步和特效事件是唯一的表现触发源；控制器不得用定时器绕开动作直接结算。

每个技能遵循短时节奏：

1. 0–180ms：前摇、目标方向和范围预警；
2. 120–500ms：武器轨迹、施法、弹道或位移；
3. 命中帧：伤害、击退、护盾、状态或治疗结算；
4. 80–300ms：受击闪白、粒子、音效、伤害数字与镜头轻震；
5. 结束：恢复控制或进入连招窗口。

普通技能总时长为 300–800ms，首领大招上限 1200ms。持续状态的回合数不等于动画播放时长。设置提供完整、简化和跳过表现：跳过只缩短表现等待，不改变命中时点、伤害或 AI 行为。

## 5. 模型、美术和动画资产

### 5.1 视觉目标

画面采用风格化 3D 海港黑暗奇幻：低饱和蓝绿雾气、暖金灯塔光、路线专属高亮色。镜头保持 45°俯视，可轻微旋转与缩放；角色在中近景尺度下移动和战斗。地图使用模块化 3D 场景，不再将平面 10×10 像素格作为最终画面。

### 5.2 资产要求与预算

最终角色必须为绑定骨骼的 glTF 或 GLB 资产，至少包括：

- 英雄莉亚：待机、走 / 跑、轻攻击、重击、施法、翻滚、受击、倒地、交互与胜利。
- 3 名 NPC：至少待机、转向和交互动作。
- 10 类敌人：至少待机、移动、攻击、受击和死亡；精英与首领额外具有蓄力、阶段转换和大招。
- 11 张地图的模块化地形、墙体、桥梁、灯塔、机关、船只、可破坏物与交互物。

验收预算：英雄 10k–25k 三角面、普通敌人 5k–15k 三角面、首领 20k–40k 三角面，配有 LOD、碰撞体和 1024 或 2048 贴图。该预算是后续资产制作条件，不代表现有项目已经拥有这些模型。

优先使用允许商业发布的 CC0 或明确商用授权素材，并在 godot_client/assets/THIRD_PARTY.md 中记录来源 URL、作者、许可证、下载日期、文件哈希和修改内容。来源不明的模型、动作、音效和贴图不得加入发布包。现有 Kenney Tiny Dungeon CC0 图块仅可用于原型参考或允许的图标 / 过渡资源，不可被描述成精细 3D 角色资产。

### 5.3 战斗表现

每项技能资源具有 id、name、cost、cooldown、target_mode、damage_formula、effects、animation_id、hit_frame、route_requirement 和本地化文案。没有 animation_id 或有效命中帧的技能不得进入可用技能池。战斗特效包括前摇地面预警、武器拖影、弹道、冲击粒子、伤害数字、状态图标、镜头轻震和路线色调；特效不可遮挡敌方预警。

## 6. 关卡、路线与结局

### 6.1 共享序章（2 关）

1. 避风站：接取灯塔任务、认识洛恩与艾芙、学习移动、交互、基础战斗和恢复。
2. 灯塔遗迹：完成三枚灯芯目标，在遗迹核心做出路线承诺。选择写入存档且在本周目不可逆。

### 6.2 守灯路线（3 关 / 结局一）

- 盐雾滩：护送港口工人，防御与补给管理。
- 灰烬码头：保护燃料车穿过灼烧区域，对抗远程与护甲敌人。
- 灯塔圣坛：灰烬领主两阶段战；结局为守住港口、点亮灯塔。

### 6.3 逐潮路线（3 关 / 结局二）

- 沉矿井：窄路、机关和伏击，探索破甲窗口。
- 潮汐洞窟：水位、迟缓地带和环境位移，管理异常状态。
- 深海裂隙：潮汐核心多阶段战；结局为封印迷雾源头。

### 6.4 破誓路线（3 关 / 结局三）

- 回声钟楼：高风险精英组合战，以生命换强化。
- 沉没档案馆：钥匙、隐藏房间与高价值技能书。
- 深海王座：王座守卫与深海权能；结局为成为新的雾中守望者。

每关有独立的 3D 场景、目标、敌人波次、技能书或收集品、出口和路线上色。LevelDefinition 至少包括 id、route_id、scene_path、objective、spawn_groups、rewards、next_level 和 palette。构建时验证路线图无死路、地图资源存在、目标可完成、奖励 ID 唯一。

## 7. 敌人、状态与技能书

保留锈齿潜伏者、潮雾胶灵、失航骸骨、熄灯者，并新增盐壳蟹、灰烬灯蛾、钟摆傀儡、深潜猎手、潮汐女巫和迷雾镜像。它们分别体现护甲 / 破甲、灼烧 / 位移、蓄力眩晕、鱼叉拉拽、减益召唤和复制上一次行动。

路线首领为灰烬领主、潮汐核心、深海王座守卫。每位首领至少两阶段，切换必须展示视觉预警、音效、可躲避或可防御的行为窗口，以及可追溯的战斗日志。

初始主动技能为普攻、破阵重击、潮汐回响和防御。状态包含灼烧、迟缓、破甲、恐惧和护盾；每个状态定义施加来源、层数、持续时间、移除条件、伤害或修正和视觉图标。

三条路线各有 3 本专属技能书，另有 2 本隐藏技能书，共 11 本。技能书获得时弹出学习 / 暂不学习；学习后永久进入本周目技能库。战斗前从已学技能中配置 4 个主动槽。技能覆盖单体爆发、扇形范围、护盾反击、净化 / 回蓝、破甲、灼烧、位移、诱饵召唤和献血爆发。

## 8. 存档、成就、控制与 Steam-ready 边界

提供 3 个手动存档位和自动存档。内容记录版本、路线、关键选择、关卡进度、技能书、四个装备技能、背包、结局、成就、统计和当前安全点。采用临时文件加原子替换；损坏存档重命名为 .broken，不静默覆盖。存档仅保存至 EXE 旁 .runtime/saves。

本地实现首次通关、三路线通关、首次学习技能书、全技能书、无伤关卡、三结局等至少 12 个成就；统计击杀、受击、技能次数、最高 DPS、技能真空、探索率和结局。SteamBridge 默认写本地 JSON，接口预留 init、unlock_achievement、set_stat 和 shutdown，未来拥有 SDK 与 App ID 后替换实现。

Godot 客户端支持鼠标、WASD、方向键、E、Esc、1–4；Gamepad 支持左摇杆移动、A 确认 / 攻击、B 返回 / 翻滚和肩键切换技能。启动器和发布包只暴露玩家可见的启动、继续、设置、退出入口；离线主线不依赖 FastAPI、DeepSeek、ComfyUI 或浏览器。

## 9. 海报与 AI 服务可靠性

结局海报优先请求可选 ComfyUI；请求超时、连接拒绝、无效 JSON、执行失败、空图片或图片超限时，统一返回本地生成的 3D 风格海报。回退海报由项目内英雄、路线首领、徽章、路线色和已授权字体或纹理合成，始终能展示和下载，不读取系统字体、不要求 GPU。

## 10. 验收标准

- Godot 客户端不依赖 Streamlit 或浏览器，双击 Windows 包后可离线开始和继续游戏。
- 11 关、3 条路线和 3 个结局均能通过自动化规则测试与可玩冒烟测试。
- 英雄、敌人和首领在最终客户端中具有可见模型和规定动作；所有可用技能在命中前播放动作与特效，且没有直接点击后立即结算的旁路。
- 11 本技能书可获取、学习、保存、读取和装备；四槽上限生效。
- 存档、成就、统计、手柄映射、离线海报和 SteamBridge 本地降级可用。
- 每项外部素材在许可证清单中可追溯；没有商业授权的资产不会被打包。
- 导出包从无源码目录、无网络、无 API Key 环境启动并完成存档、路线选择、技能、首领、海报和退出清理验证。

## 11. 不在本轮承诺的事项

- 不伪造 Steam App ID、商店页、评论、Steamworks 上传或审核结果。
- 不把未获得授权的网络模型、动作、音效或贴图加入项目。
- 不承诺在缺少 Godot 4、Blender、可商用模型与动作资源的环境中凭空产出高精度手工建模资产；这些工具与资产将在后续实现阶段以 E 盘本地安装、明确许可和验收为前提。
- Python / Streamlit 版本可继续作为策划验证台，但不作为最终 3D 玩家客户端。
